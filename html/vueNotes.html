    Notes

    • refs
      • Reference an element by putting ref="elementName" in the element html. Then in the js, write this.$refs.elementName to get the current element!
      • Vues documentation on refs.
    • Using Vue
      • In your HTML put a div around what you want to use view and give it the id of app.
      • In your script (which is in your body tag) get createApp and ref from Vue {createApp, ref} = Vue
      • Create your Vue app instance createApp({})
      • Within createApp add the setup function and use it to define your data createApp({ setup(){ const dataThing = ref('whatever you want') return dataThing } })
      • Add mount with the id you want your vue code mounted on at the end of createApp createApp({...}).mount('#app')
    • To get vue on your project in your terminal write npm create vue@latest, say yes you'd like to proceed, choose your projects location (use . for the current directive), give your project a name, choose what you want to include, run npm install, then npm run dev.
    • Vue Project Anatomy
      • src folder
        • The assets folder holds the assets off your project (shocking) like css
        • The compoennts holds the pre-uploade icons
        • App.vue is the home of your project
        • main.js linkes all your files together
      • The index.html file is your main html file.
      • The jsconfig.json file determines which files should be compiled when we build the project.
    • Vue Component
      • The Vue component is a special file format that contains the HTML CSS and JS in one package.
      • The structure is like <script setup> JAVASCRIPT GOES HERE </script> <template> HTML GOES HERE </template> <style scoped> CSS GOES HERE </style>
      • The naming convension for a Vue component is Name.vue
    • Separation of concerns is not equal to separation of file types. Vue focuses more on separation by concern instead of file type specifically.
    • Layout Components
      • Sometimes called structural components.
      • Examples include Header Main and Footer.
    • To import another component into App.vue in the script area import Name from @/components/Name.vue and in the template <Name />
    • The App file is the top level component that pulls all other components together.
    • The @ Alias
      • @ can be used as a path indecator.
      • Given to us by Vite
      • tells vite if it sees @ replace the file path to ./src, always taking use back to the src file and moving from there.
    • npm i && npm run dev
    • Reactivity Basics
      • A reactive state is something vue does that watches certain variables for change and rerenders the component if the value changes
    • Template Syntax
      • Text Interpolation
        • This is when you use {{whatever}} to place a specific ref in your html.
        • You can change the value of a ref in the script by using .value refName.value = 'new value'
      • Attribute Binding
        • Helps us bind data to HTML attributes.
        • Vue uses the v-bind directive. v-bind attributes are data bound. <a v-bind:href="hrefRef">
        • v-bind works with boolean attributes (like disabled) too! v-bind:disabled="isBtnDisabled"
        • v-bind has shorthand which is just the colon. :disabled="isBtnDisabled"
        • If the attribute value is the same as the sign you can remove the =value. :href is equal to v-bind:href="href"
      • Images In Vue
        • Absolute Path
          • Absolute path to /public folder. It is for static assets. They don't go through the bundling process and don't get optimized. Any file in thepublic folder canbe accessed directly via the root slash URL.
            <img src="/images/imageName.jpg" />
          • The absolute path is best for large and/or static assets that don't need optimisation (pdfs).
          • The absolute path is simple and straightforward, files that are served as-is, and is very accessible from external CSS files.
          • The absolute path has no Vite optimization, is harder to organize, and may not update due to browswer caching.
        • Relative Path
          • Relative path to /assets folder. assets folder is in src folder. Images can live here, referenced using @/assets/... <img src="@/assets/images/imageName.jpg" />>
          • The relative path is best for small, static assets in simple projects.
          • The relative path is super easy and works without special imports.
          • The relative path does not have Vite optimization, has no dynamic images, and is not modular.
        • Importing Assets
          • Import assets into component. involves importing it from the assets folder and then binding it to an image source attribute. import imageName from "@/assets/images/theimageName.jpg" and in the template <img :src="imageName" />
          • Importing assets is best for dynamic images (product photos).
          • Importing assets is optimized by Vite, has conditional loading, and is modular and scalable.
          • Importing assets is more verbose and may be confusing at first.
